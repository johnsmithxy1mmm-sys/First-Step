# First Step — конвейер инвестиционных меморандумов

Один YAML-файл объекта на входе → один брендированный PDF-меморандум на выходе.

```bash
python generate.py objects/park.yaml
# -> out/park-memo.pdf
```

Финансовая модель (DCF + Монте-Карло + чувствительность) и шаблон отчёта
настраиваются один раз и переиспользуются. Чтобы собрать новый меморандум,
достаточно заполнить один конфиг объекта и запустить команду.

Есть два способа работы:

- **Графическое приложение** (окно с формой) — для повседневной работы без
  командной строки. См. раздел «Приложение с интерфейсом».
- **CLI** (`python generate.py ...`) — для автоматизации и пакетной сборки.

---

## Приложение с интерфейсом (Windows)

Окно с формой: заполняете параметры объекта → «Сформировать PDF» → готовый
меморандум в папке `out/`. Можно загрузить/сохранить параметры как YAML.

**Запуск из исходников** (быстро, без сборки):

1. Установите Python 3.11+ с [python.org](https://www.python.org/downloads/)
   (отметьте «Add python.exe to PATH»).
2. Двойной клик по `run_app.bat` — первый запуск поставит зависимости и
   откроет окно.

**Сборка в `.exe`** (чтобы запускать двойным кликом, без Python):

1. Двойной клик по `build_windows.bat`.
2. Готовое приложение появится в `dist\Memorandums\Memorandums.exe`.
   Папку `dist\Memorandums` можно целиком перенести на другой компьютер.
   (Имя файла латиницей — так надёжнее в Windows; окно внутри на русском.)

> `.exe` собирается только на Windows (PyInstaller компилирует под текущую ОС).
> При первом формировании PDF приложение один раз скачивает движок рендера
> (Chromium, ~150 МБ) — нужен интернет.

**Если установка падает с ошибкой про прокси / SOCKS.** Батники сами включают
поддержку SOCKS (офлайн-пакет `pysocks` из папки `vendor/`) и при сбое
повторяют установку в обход прокси (`--proxy ""`) — отдельных действий не
требуется. Если установка всё равно не идёт из-за очень свежего Python 3.14,
надёжнее поставить рядом Python 3.12 с [python.org](https://www.python.org/downloads/).

## Установка

Нужен Python 3.11+.

```bash
pip install -r requirements.txt
playwright install chromium      # один раз: ставит headless-Chromium для рендера PDF
```

> Версия `playwright` в `requirements.txt` зафиксирована под ревизию браузера.
> Если `playwright install chromium` жалуется на несовпадение версии — оставьте
> версию из `requirements.txt`, она согласована с движком рендера.

## Как собрать меморандум за одну команду

1. Скопируйте любой пример из `objects/` и отредактируйте параметры объекта:

   ```bash
   cp objects/park.yaml objects/my-object.yaml
   # отредактируйте objects/my-object.yaml
   ```

2. Соберите PDF:

   ```bash
   python generate.py objects/my-object.yaml
   # -> out/my-object-memo.pdf
   ```

Опции:

| Опция | Назначение |
|---|---|
| `--out PATH` | путь к выходному PDF (по умолчанию `out/<имя>-memo.pdf`) |
| `--date ГГГГ-ММ-ДД` | дата меморандума (по умолчанию сегодня) |
| `--seed N` | переопределить сид Монте-Карло из конфига |
| `--html` | сохранить также промежуточный HTML рядом с PDF |

При кривом конфиге команда печатает понятные ошибки на русском (что и где
поправить) и завершается без сборки PDF.

## Конфиг объекта (YAML)

Минимум обязательного, разумные значения по умолчанию, все допущения — явные.
Полностью прокомментированные примеры: `objects/park.yaml` (пресейл с рассрочкой,
выход через прирост цены, `HOLD`) и `objects/polyana.yaml` (готовый доходный
объект, выход через капитализацию дохода, `ACQUIRE`).

Ключевые блоки:

- `object` — название, застройщик, зона, тип, площадь.
- `purchase` — цена и график рассрочки (`schedule`: транши `{month, pct}`,
  доли должны сходиться к 100 %).
- `operations` — ставка аренды, загрузка, OPEX, рост ставки, месяц начала
  аренды (`rent_start_month` — для пресейла «до ввода» поставьте месяц ввода).
- `exit` — горизонт удержания и способ оценки выхода: либо
  `exit_cap_rate_pct` (капитализация дохода), либо `exit_price_growth_pct`
  (годовой прирост цены). Достаточно одного.
- `assumptions` — ставка дисконтирования и целевой IRR.
- `monte_carlo` — число итераций, сид и стохастические `ranges`
  (`triangular` / `normal` / `uniform`).
- `advisor` — рекомендация (`ACQUIRE` / `HOLD` / `AVOID`), тезис, сценарий
  выхода, подпись.

## Что внутри PDF

Многостраничный меморандум в айдентике Ink / Paper / Brass:

1. Обложка — объект, застройщик, микрозона, дата, «Конфиденциально», подпись.
2. Резюме — печать-штамп рекомендации, тезис, ключевые метрики.
3. Параметры объекта — компактная таблица входных данных.
4. Финансовая модель (DCF) — таблица годовых потоков, NPV, IRR, окупаемость,
   доходность; водопад денежных потоков.
5. Монте-Карло — гистограмма IRR с P5/P50/P95 и целевым порогом, вероятности
   недобора и убытка.
6. Чувствительность — торнадо-диаграмма вклада допущений.
7. Структура рассрочки — транши и их влияние на тайминг.
8. Сценарий выхода.
9. Дисклеймер.

Колонтитул с подписью, пометкой «Конфиденциально» и нумерацией страниц — на
всех листах, кроме обложки.

## Финансовый движок

Модуль `finance/` — чистые функции, покрытые `pytest`, без зашитых чисел:

- `dcf.py` — помесячные потоки (учёт тайминга траншей рассрочки), NPV, IRR,
  простая и дисконтированная окупаемость, валовая/чистая доходность, MOIC,
  терминальная стоимость (cap rate или рост цены).
- `monte_carlo.py` — симуляция распределения IRR, перцентили, вероятности.
- `sensitivity.py` — торнадо-анализ.
- `installment.py` — разворот графика рассрочки в денежные потоки.
- `format_ru.py` — форматирование `ru-RU` (₽, разделители, проценты).

Каждое финансовое допущение прокомментировано прямо в коде.

### Тесты

```bash
python -m pytest
```

Проверяются: IRR на известных кейсах, согласованность NPV/IRR, влияние тайминга
рассрочки, сходимость долей к 100 %, граничные значения, воспроизводимость
Монте-Карло по сиду, форматирование и сообщения валидации.

## Детерминированность

Одинаковый вход (и сид, и `--date`) даёт **байт-в-байт одинаковый PDF**: сид
Монте-Карло фиксирован, графики рендерятся в SVG-контуры, шрифты встроены,
а временные метки PDF нормализуются под дату меморандума.

```bash
python generate.py objects/park.yaml --date 2026-06-11 --out a.pdf
python generate.py objects/park.yaml --date 2026-06-11 --out b.pdf
cmp a.pdf b.pdf   # файлы идентичны
```

## Что и где править

| Хочу изменить | Где |
|---|---|
| Параметры конкретного объекта | `objects/<имя>.yaml` |
| Бренд-палитру, типографику, вёрстку | `report/assets/brand.css` |
| Состав и порядок секций | `report/templates/memorandum.html.j2` |
| Стиль графиков | `report/charts.py` (палитра вверху файла) |
| Финансовые допущения и формулы | `finance/` (с комментариями) |

Структура проекта:

```
app.py                       графический интерфейс (форма -> PDF)
appcore.py                   ядро приложения (валидация, рендер, без GUI)
generate.py                  CLI: YAML -> PDF
run_app.bat                  запуск формы из исходников (Windows)
build_windows.bat            сборка .exe (Windows)
first_step.spec              спецификация PyInstaller
finance/                     движок DCF + Монте-Карло (+ тесты)
config/                      схема и валидация конфига
report/                      графики, HTML-шаблон, сборка PDF
  assets/brand.css           бренд-токены и вёрстка
  assets/fonts/              встроенные шрифты Lora
  templates/                 Jinja2-шаблон меморандума
objects/                     конфиги объектов (примеры внутри)
out/                         готовые PDF
tests/                       pytest
```
