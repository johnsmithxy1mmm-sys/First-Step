## A-01 `Book.with_position` фабрикует equity при reduce/flip

- **Severity:** High — функция задокументирована как основа `pre_trade_delta`
  (§4.2) и `max_safe_size` (§4.3); величина искажения не ограничена и включает
  §10-запрещённое направление (занижение риска). Латентна: вызывающих путей в
  Фазе 1 нет, дефект сработает в первый день Фазы 2.
- **Confidence:** Подтверждено. **Категория:** корректность / доменный инвариант.
- **Расположение:** `risk_engine/domain/types.py:188` (`Book.with_position`, ветка `prior.side != position.side`)

**ФАКТ.** Книга: $50k cross-cash, +2 BTC @ 100k, спот 90k → equity $30 000.
- `with_position(−1 BTC @ 90k)` → equity **$40 000** (+$10k из ничего);
- `with_position(−5 BTC @ 90k)` → остаток −3 BTC с `entry=100 000` → equity **$80 000** (+$50k).

Механизм: при уменьшении позиции реализованный PnL закрытой части
(`closed_size·(exec_price − prior.entry)`) не зачисляется в `cross_collateral`,
а при флипе новая позиция противоположного знака наследует entry старой.

**ПОЧЕМУ ЭТО ДЕФЕКТ.** Закон сохранения (Фаза 7): закрытие по рыночной цене не
меняет equity — сумма до обязана равняться сумме после. Gherkin:
`Given книга с лонгом в убытке / When гипотетический ордер уменьшает позицию по рынку / Then equity гипотетической книги равен equity исходной`. Нарушено в обе
стороны: закрытие в убыток завышает equity → `pre_trade_delta` покажет
заниженный P(liq) «после» (§10), закрытие в прибыль занизит → ложная тревога.

**PoC:** `audit_poc.py` F-01, выведено `+10,000 / +50,000 REPRODUCED`.

**ВОЗДЕЙСТВИЕ.** Всё, что Фаза 2 посчитает для reduce/flip-ордеров, будет
арифметически неверным; для `max_safe_size` бинарный поиск получит немонотонную
цель.

**ИСПРАВЛЕНИЕ.** В ветке противоположных сторон: `closed = min(|prior.size|,
|position.size|)`; `realized = ±closed·(position.entry_price − prior.entry_price)`
(знак по стороне prior); для cross — `cross_collateral += realized`, для
isolated — в маржу кармана с высвобождением; при флипе остаток получает
`entry = position.entry_price`.

**ТЕСТ.** Property-based: для любых prior/order/спота
`with_position(order).equity(spot) == book.equity(spot)` при `order.entry_price
== spot` (исполнение по рынку). Сегодня красный.

**ДОПУЩЕНИЯ.** Нет: дефект доказан на чистой арифметике типа.

## A-02 PIT §3.3 отвергает идеально калиброванную модель при атоме ликвидации

- **Severity:** High — ломает главный денежный гейт (§3.3/§0.3) в направлении
  «фейл-сейф, но неустранимо»: когорта с материальной частотой ликвидаций
  никогда не пройдёт KS, сколько бы данных ни накопилось. Гейт Фазы 4
  недостижим не из-за модели, а из-за метрики.
- **Confidence:** Подтверждено (аналитически + численно). **Категория:** методология валидации.
- **Расположение:** `risk_engine/sim/stats.py:150` (`PredictiveDistribution.pit`) + `risk_engine/liquidation/simulator.py::_terminal_equity` (источник атома: equity ликвидированного пула → ровно 0).

**ФАКТ.** §1.6-упрощение пишет terminal equity ликвидированного пула нулём →
предсказанное распределение имеет атом в точке −start_equity. `pit()` — это
`np.interp` по квантильной функции: все фактические ликвидации получают ОДНО
детерминированное значение PIT (верхний край атома). PoC: истинный закон = 20%
атом + N(0,100); прогноз построен из того же закона; 3000 фактов из того же
закона → все ликвидации дают PIT=0.199, KS statistic 0.1990,
**p-value 1.35e-104** при идеальной калибровке по построению.

**ПОЧЕМУ ЭТО ДЕФЕКТ.** PIT равномерен только для непрерывных прогнозных
распределений; при атомах требуется рандомизированный PIT
`u ~ U(F(x⁻), F(x))`. Gherkin: `Given модель, предсказывающая истинный закон /
When накоплен shadow-период / Then PIT-тест проходит` — код не удовлетворяет
сценарию для любой когорты с ненулевой частотой ликвидаций.

**ВОЗДЕЙСТВИЕ.** Shadow-валидация систематически «краснит» именно на самых
рискованных адресах — тех, ради которых продукт существует; либо гейт вечно
закрыт, либо (хуже) его «починят» ослаблением. Смежно: CRPS от атома корректен,
VaR-breach корректен — испорчен только PIT/KS.

**ИСПРАВЛЕНИЕ.** Рандомизированный PIT в резолвере: хранить
`F(x⁻)` и `F(x)` (левый/правый пределы по квантильной функции), PIT = сид-детерминированная
равномерная точка между ними; сид писать в строку исхода (воспроизводимость).

**ТЕСТ.** Сегодняшний PoC как тест: прогноз из закона с атомом, факты из того
же закона → KS p-value > 0.01. Красный до фикса.

**ДОПУЩЕНИЯ.** Нет; масштаб эффекта пропорционален P(liq) когорты (для
низкорисковых адресов эффект мал — что маскирует дефект в ранних прогонах).

## A-03 Baseline B не независим: t-копула при ρ=0 сохраняет хвостовую зависимость

- **Severity:** Medium — целостность решающего сравнения §3.2/§0.2.
- **Confidence:** Подтверждено. **Категория:** корректность / методология.
- **Расположение:** `risk_engine/sim/engine.py::ModelBundle.path_spec(independent=True)` (corr=I при неизменном `copula_df`); также мёртвый `PathSpec.independent()`.

**ФАКТ.** «Независимый» бейзлайн строит пути с corr=I, но тем же χ²-миксером
t-копулы (одна тяга на путь-шаг, общая для всех активов). PoC (400k путей,
ν=4, ρ=0): P(актив B в худших 5% | актив A в худших 5%) = **0.1295** против
0.0500 при независимости; собственная функция кода
`model_tail_dependence_at_threshold(4.0, 0.0, 0.05)` подтверждает 0.1278.

**ПОЧЕМУ ЭТО ДЕФЕКТ.** §3.2 определяет бейзлайн Б как «независимые пути по
активам (ρ=0)». Некоррелированность ≠ независимость для эллиптической t.
Нулевая гипотеза тайно содержит совместные крахи — главный эффект, который
сравнение должно изолировать. Направление двоякое: гейт §0.2 становится строже
(фейл-сейф), но предписанный §3.2 вывод «полная модель не бьёт Б → упростить,
выбросить корреляционную машинерию» станет ложным управленческим решением:
Б сам построен на этой машинерии.

**PoC:** `audit_poc.py` F-02.

**ИСПРАВЛЕНИЕ.** Для independent=True использовать `copula_df=None`
(гауссова копула + corr=I ⇒ истинная независимость, маргиналы Student-t не
меняются — квантильная карта None→df уже реализована и оттестирована).
Удалить мёртвый `PathSpec.independent()` или использовать его же с фиксом.

**ТЕСТ.** Для independent-прогона: эмпирическая joint-tail-частота на путях
= 5% ± MC-погрешность (сегодня 13% — красный).

**ДОПУЩЕНИЯ.** Прочтение «независимые» буквально; альтернативное прочтение
«ρ=0 в той же копуле» противоречит цели сравнения, но если владелец спецификации
подтвердит его — дефект переквалифицируется в неоднозначность спецификации.

## A-04 Резолвер молча скорит опоздавшие разрешения

- **Severity:** Medium — тихая порча калибровочной выборки, главного рва продукта (§3.4).
- **Confidence:** Подтверждено. **Категория:** корректность / данные.
- **Расположение:** `risk_engine/shadow/resolve.py::resolve_due` (нет ограничения на `now − resolves_at`); `shadow/metrics.py::load_cohort` (не фильтрует по лагу).

**ФАКТ.** PoC: прогноз с горизонтом 24ч; `resolve_due(now = t0+72ч)` —
разрешено без ошибок, изменение equity за 72ч записано против 24ч-распределения,
PIT=0.000, строка вошла в когорту метрик. Поле `resolved_at` сохраняется, но
никто его не читает.

**ПОЧЕМУ ЭТО ДЕФЕКТ.** Контракт §3.3: факт сравнивается с прогнозом **своего
горизонта**. Gherkin: `Given резолвер не запускался 2 суток / When он
запускается / Then 24ч-прогнозы либо скорятся по состоянию на resolves_at, либо
помечаются невалидными` — код не удовлетворяет: Info API не даёт исторического
состояния, значит честный выход — пометка, не скоринг. Дисперсия 72ч-изменения
втрое выше → PIT сместится к краям → ложный сигнал «модель недооценивает хвосты».

**ИСПРАВЛЕНИЕ.** В `resolve_due`: если `now − resolves_at > tolerance`
(напр. 2ч) — писать исход с флагом `stale_resolution` (новая колонка) и
исключать из когорт по умолчанию; счётчик в observability (§7).

**ТЕСТ.** `resolve_due(+72h)` → строка помечена stale, `load_cohort` её не
включает. Красный до фикса.

**ДОПУЩЕНИЯ.** Крон-инфраструктура может гарантировать своевременность — но в
коде гарантии нет, а §6 явно требует проектировать под отказ.

## A-05 Выживший мутант M1: интенсивность шринкаджа не проверяется

- **Severity:** Medium — Ledoit-Wolf объявлен «обязательным» (§2.1), но тесты
  не отличают корректную интенсивность от `intensity=1.0` (полная замена
  выборочных корреляций эквикорреляцией).
- **Confidence:** Подтверждено живым прогоном. **Категория:** тесты.
- **Расположение:** `risk_engine/model/shrinkage.py` (формула интенсивности); тесты `test_model.py::TestShrinkage`.

**ФАКТ.** Мутация `(pi - rho) / gamma / n_eff` → `* n_eff` (клип до 1.0 ⇒
полный сдвиг к таргету) — **вся выборка `TestShrinkage` + `TestGlobalMatrix`
зелёная** (живой прогон в этой сессии).

**ПОЧЕМУ ЭТО ДЕФЕКТ.** Тесты проверяют только направление (|shrunk| < |raw|) и
сохранение дисперсий — свойства, которые выполняет и вырожденный оценщик.
Величина интенсивности, ради которой существует адаптация A5, фактически не
покрыта проверкой смысла.

**ТЕСТ-УБИЙЦА.** Сходимость: на iid-выборке n=50 000, A=5 интенсивность < 0.05
(асимптотика LW → 0 при n→∞); и на n=80, A=12 интенсивность в (0.05, 0.95)
строго внутри.

## A-06 Выживший мутант M2: форма импутированной строки молодого актива

- **Severity:** Medium — §2.1 называет недооценку корреляций новых листингов
  «опаснейшим дефектом», но половина конструкции гейта не закреплена тестом.
- **Confidence:** Подтверждено живым прогоном. **Категория:** тесты.
- **Расположение:** `risk_engine/model/correlation.py::build_global_matrix` (цикл импутации); тесты `TestGlobalMatrix`.

**ФАКТ.** Мутация `rho = gate_rho * corr_mature[anchor_i, j]` → `rho = gate_rho`
(одинаковая корреляция со всеми зрелыми активами, потеря однофакторной
структуры) — **все тесты `TestGlobalMatrix` зелёные** (живой прогон).

**ПОЧЕМУ ЭТО ДЕФЕКТ.** Проверяется только ячейка «молодой↔якорь» и
независимость от собственной выборки; ячейки «молодой↔прочие зрелые» — нет.
Мутант завышает корреляции с антикоррелированными якорю активами → искажает
P(liq) хеджированных книг в непредсказуемую сторону.

**ТЕСТ-УБИЙЦА.** `corr[young, j] == gate_rho * corr[anchor, j]` для каждого
зрелого j ≠ anchor (до PSD-проекции; после — с допуском).

## A-07 NaN проходит все слои валидации до журнала калибровки

- **Severity:** Medium-Low. Исходная гипотеза аудита («NaN глушит P(liq) до
  нуля») **опровергнута PoC**: строгое `cross_alive &= gap > 0` на t=0 делает
  NaN-путь мёртвым немедленно → P(liq)=1, консервативно. Остаточный дефект:
  NaN-числа из API принимаются парсером и типами и доезжают до журнала.
- **Confidence:** Подтверждено. **Категория:** робастность / taint.
- **Расположение:** `market/parse.py::_f` (float() без isfinite); `domain/types.py::Position.__post_init__` (`NaN <= 0` → False → пропуск); `sim/stats.py::PredictiveDistribution.__post_init__` (`np.diff(NaN) < 0` → False → NaN-квантили валидны).

**ФАКТ.** `szi="NaN"` парсится в позицию; PoC: `PredictiveDistribution` из
NaN-выборки проходит валидацию, `pit/crps = nan`, `ks_uniformity → (nan, nan)`.
Гейт при этом читает FAIL (nan-сравнения дают False) — фейл-сейф, но
диагностика мусорная и shadow-окно сжигается впустую.

**ИСПРАВЛЕНИЕ.** `_f()`: `math.isfinite` или отказ; `PredictiveDistribution`:
`np.isfinite(values).all()` в `__post_init__`. Два однострочника закрывают
весь класс.

**ТЕСТ.** `parse_clearinghouse_state` с `"NaN"`/`"inf"` → ValueError;
`PredictiveDistribution.from_samples([nan])` → ValueError.

## A-08 Фолбэк на `marginSummary` двойным счётом завышает cross-обеспечение

- **Severity:** Medium (при срабатывании — завышение equity → занижение риска, §10-направление).
- **Confidence:** Вероятно — зависит от семантики API, недоступного из этой среды (E5).
- **Расположение:** `market/parse.py::parse_clearinghouse_state` (`state.get("crossMarginSummary") or state.get("marginSummary")`).

**ФАКТ.** При отсутствии `crossMarginSummary` код берёт
`marginSummary.accountValue` как cross-account-value. По документации HL
`marginSummary` — сводка ВСЕГО аккаунта, включая isolated-карманы. Тогда
`cross_collateral = accountValue_total − cross_upnl` включает isolated-маржу,
которая затем считается второй раз в `Position.isolated_margin` →
`Book.equity` завышен на сумму isolated-маржи.

**ИСПРАВЛЕНИЕ.** Убрать фолбэк: отсутствие `crossMarginSummary` → ValueError
(парсер и так строгий везде, кроме этого места). Если live-API покажет, что
поле бывает легитимно отсутствующим — вычитать isolated-маржу явно.

**ДОПУЩЕНИЯ.** Семантика полей — по документации; если `marginSummary`
фактически cross-only, дефекта нет (проверить при снятии E5).

## Taint-анализ — итог

Источники: Info API (числа-строки, формы ответов), адреса, путь журнала из CLI.
Стоки: SQLite (всё параметризовано — чисто), симулятор (деньги), журнал.
Единственный сквозной проход: **нефинитные числовые строки** (A-07) и

## Пробелы покрытия (не дефекты, а границы доказанного)

1. Точность bridge-коррекции проверена только на гауссовых маргиналах
   (benchmark 3.1.1); при t-маргиналах с χ²-миксером условная дисперсия шага
   внутри моста аппроксимируется безусловной — величина ошибки не измерена.
2. Многотировые траектории: закрытые формы `margin.py` фиксируют mmr
   (задокументировано), но нет теста, сравнивающего симулятор с закрытой формой
   при пересечении тира по пути.
3. Эскалация путей: последовательный стоп-критерий (остановка при узком CI)
   даёт малое смещение оценки — не квантифицировано.
4. `parse_meta`/`parse_clearinghouse_state` — формы из документации, не из
   живых ответов (E5): всё покрытие фикстурное.
5. CI-интервалы cross/isolated не подчинены правилу 2 pp — эскалация смотрит
   только на `p_liq_any`.
6. Запись трёх вариантов прогноза в кроне неатомарна (3 коммита);
   частичная запись деградирует фейл-сейф, но не тестируется.

## Проверено и чисто (метод: ручная верификация + тесты)

- Алгебра `_liq_from_margin_available` сверена выводом из условия §1.1 (совпадает точно, включая |size| для шорта).
- Формулы Ledoit-Wolf (π, ρ, γ, cross-члены) сверены с LW-2003 почленно — адаптация корректна (величина интенсивности — см. A-05).
- PSD-сдвиг `(C+sI)/(1+s)`: алгебраически даёт min-eig ровно floor, диагональ ровно 1.
- Знак фандинга (лонг платит при положительной ставке), начисление на карман isolated, остановка начисления после смерти пула.
- CRPS через pinball-тождество; CVaR из квантильной функции; интервалы Вильсона.
- Лексикографическое сравнение ISO-таймстампов в SQLite (`'+' < '.' < цифры` — упорядочение корректно и для микросекундных/безмикросекундных строк).
- Независимость N+1 условий ликвидации (§1.1) — пул/карманы не связаны ни PnL, ни фандингом.
- Параметризация SQL; отсутствие секретов в коде и логах.

Отсутствие прочих находок — утверждение о границах статического анализа и
фикстурного тестирования, не о корректности программы: живой API (E5) остаётся
непроверенным целиком.
